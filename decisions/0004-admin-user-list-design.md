# 0004. 管理者向けユーザー一覧画面の設計

## 状態

採用

## 背景

ロールベース認可(decisions/0001〜0003)は実装済みだが、ユーザーへのロール割り当てを操作する画面はまだ無かった。
README.md にも「ユーザーへのロール割り当てを操作する画面は、ユーザーを検索するAPIが無いため未実装のまま」と
明記されており、この欠落を解消するには数千件規模を想定したページング・絞り込み・ソート付きの一覧画面が必要になる。

これを実装するにあたり、トレードオフのある3つの決定が絡む。

- 数千件規模でのページング方式。
- 標準の `IdentityUser` には登録日時のようなカラムが無く、ソート対象に含めるには追加が必要。既存ユーザーへの
  バックフィル方法も決める必要がある。
- 新規一覧APIに、既存の `Admin.UserRoles`(ロール割り当て)とは別の権限キーを設けるかどうか。

## 検討した選択肢

- ページング方式
  - 案A: オフセットページング(`page`/`pageSize` + `Skip`/`Take` + 総件数)
    - 長所: 実装が単純。総件数・任意ページへのジャンプを素直に表現できる。
    - 短所: `Skip` の件数が非常に大きくなると(数十万件規模)コストが増える。
  - 案B: キーセット(カーソル)ページング
    - 長所: 件数が増えても性能が安定する。
    - 短所: 「前へ/次へ」以外のUI(任意ページへのジャンプ、総件数表示)が作りにくい。実装・テストの複雑さが増す。
- `CreatedAt` カラムの追加方法
  - 案A: NULL許容のカラムを追加し、既存ユーザーはバックフィルせず `NULL`(登録日時不明)のままにする。
    ソート時は `NULL` を並び順にかかわらず末尾に固定する。
    - 長所: 実データと「本当は分からない」ことを区別できる。捏造したデータを持ち込まない。
    - 短所: 既存ユーザーの行は登録日時でのソートが「常に末尾」という特別扱いになる。
  - 案B: NOT NULL カラムとし、既存ユーザーにはマイグレーション適用時刻などを一律バックフィルする。
    - 長所: 全行が同じ土俵でソートできる。NULL 分岐が不要になる。
    - 短所: バックフィルした値は実際の登録日時ではなく、後から実データと見分けがつかなくなる。
- 権限キー
  - 案A: 新規 `Admin.Users` キーを設ける。
    - 長所: 「ユーザー一覧の閲覧」と「特定ユーザーへのロール割り当て」を独立した権限として分離できる。
      ADR 0001 の「権限粒度はアクション単位」という方針に沿う。
    - 短所: 権限キーが1つ増える。ロール割り当て担当者には別途 `Admin.Users` も付与する必要がある。
  - 案B: 既存の `Admin.UserRoles` を流用する。
    - 長所: 権限キーが増えない。
    - 短所: 一覧の閲覧(全ユーザーのメールアドレス・登録日時の開示)と、特定ユーザーへのロール割り当てという
      性質の異なる操作が同じ権限に紐づき、閲覧のみを許可したい場合に対応できない。

## 決定

いずれも案Aを採用する。オフセットページング、`CreatedAt` は NULL許容・バックフィルなし(NULLは常に末尾)、
権限キーは新規 `Admin.Users` とする。

## 理由

現在の想定規模(数千件)ではオフセットページングのコストは問題にならない。キーセットページングが必要になるほど
件数が増えた場合に改めて検討すれば十分である。

存在しない日時を捏造してバックフィルすると、後から見て「実際の登録日時」なのか「移行時に入れた値」なのかを
区別できなくなる。NULL のまま保持し、UI・API 双方で「不明」として扱う方が誠実である(decisions/0002の
「不要な保険コードを書かない」という姿勢とも整合する)。

一覧の閲覧は、個別ユーザーへのロール割り当てより広い情報開示(全ユーザーのメールアドレス・登録日時)を伴う。
ADR 0001 が確立した「権限粒度はアクション単位」という方針に従い、独立した権限として分離する。

## 影響

- 新規マイグレーション `AddApplicationUserCreatedAt`(`AspNetUsers.CreatedAt`, `datetime2`, NULL許容)を追加した。
- 標準 `IdentityUser` を直接使っていた箇所を `ApplicationUser : IdentityUser` に置き換えた
  (`AuthDbContext`・`Program.cs`・`AuthController`・`AdminBootstrap`・`PermissionAuthorizationHandler`・
  `UserRolesController` およびテストコード)。
- 新規 `UsersController`(`GET /api/admin/users`)と権限キー `Admin.Users` を追加した。
- ソート列は SQLite プロバイダの制約により `DateTimeOffset` ではなく `DateTime`(UTC)として保持する
  (SQLite は `ORDER BY` での `DateTimeOffset` 比較をサポートしないため)。
- 見直す条件: ユーザー数が数十万件規模まで増え、オフセットページングのコストが実測で問題になった場合、
  キーセットページングへの移行を検討する別のADRを起こす。
