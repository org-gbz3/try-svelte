# 0005. ユーザー一覧のメール検索オプション(前方一致・大文字小文字区別)の実装方式

## 状態

採用

## 背景

管理者向けユーザー一覧画面(decisions/0004)のメール検索に、「前方一致検索の ON/OFF」「大文字小文字を区別の ON/OFF」
という2つのオプションを追加することになった。

従来の実装は `EF.Functions.Like(user.Email!, "%検索語%", "\\")` のみで、部分一致・大文字小文字を区別しない
検索を行っていたが、この「区別しない」という挙動は明示的に実装したものではなく、本番の SQL Server の既定の
照合順序(大文字小文字を区別しない設定が一般的)と、テストで使う SQLite の LIKE の仕様(後述)がたまたま
どちらも大文字小文字を無視する、という偶然の一致に依存していた。

オプションを追加するにあたり、この暗黙の依存のままでは「大文字小文字を区別する」を確実に実現できない。特に
SQLite の LIKE は `case_sensitive_like` プラグマを設定しない限り常に ASCII の大文字小文字を無視する仕様であり、
これは `COLLATE` 句を明示的に指定しても変わらない(LIKE 自体の実装が照合順序と独立に大文字小文字を畳み込むため)。
一方 SQL Server は `COLLATE` 句で照合順序を明示すれば大文字小文字の区別を制御できる。つまり両プロバイダで
制御方法そのものが異なる。

## 検討した選択肢

- 大文字小文字を区別しない検索の実装方法
  - 案A: Identity が既に保持している正規化済み(大文字化済み)の `NormalizedEmail` と、検索語を
    `ToUpperInvariant()` したパターンを比較する。
    - 長所: DB の既定の照合順序や LIKE の大文字小文字の扱いに依存せず、両プロバイダで同じ結果になる。
    - 短所: `Email` ではなく `NormalizedEmail` を検索対象にする変更が必要。
  - 案B: 従来どおり `Email` に対する LIKE のみで済ませる。
    - 長所: 変更が小さい。
    - 短所: 挙動が DB の既定の照合順序に暗黙に依存したままになる。
- 大文字小文字を区別する検索の実装方法
  - 案A: DB プロバイダで分岐し、SQL Server は `EF.Functions.Collate` で大文字小文字を区別する照合順序を
    明示し、SQLite は `PRAGMA case_sensitive_like = ON` を検索直前に発行する。
    - 長所: 数千件規模でも DB 側の LIKE でそのまま絞り込め、decisions/0004 のオフセットページングの前提
      (DB 側での絞り込み)を崩さない。
    - 短所: プロバイダ判定の分岐が増える。
  - 案B: アプリ側で全件取得し、C# の文字列比較で絞り込む(クライアント評価)。
    - 長所: プロバイダ差を意識しなくてよい。
    - 短所: 数千件規模を毎回全件取得することになり、decisions/0004 が前提とするオフセットページングの
      コスト特性(DB 側で絞り込んでからページングする)と矛盾する。

## 決定

いずれも案Aを採用する。大文字小文字を区別しない検索は `NormalizedEmail` を使い、区別する検索は DB プロバイダ
(`Database.ProviderName`)で分岐して SQL Server は `COLLATE`、SQLite は `PRAGMA case_sensitive_like` を使う。
前方一致・部分一致は同じ LIKE パターンの組み立て方(`検索語%` か `%検索語%`)を両方の分岐で共通に使う。

## 理由

「区別しない」検索を LIKE の既定挙動に頼るのをやめて `NormalizedEmail` ベースにすることで、大文字小文字の
畳み込みが DB のバージョンや設定に依存しなくなり、テスト(SQLite)と本番(SQL Server)で同じ結果になることを
保証できる。

「区別する」検索は、SQLite の LIKE が照合順序と独立に大文字小文字を畳み込む仕様である以上、`COLLATE` 句だけでは
実現できない。DB 側で絞り込みを完結させたまま両プロバイダに対応するには、プロバイダごとに区別を強制する方法を
分けるほかない。クライアント評価(案B)は decisions/0004 が前提とする「数千件規模でも DB 側の絞り込みで
コストを抑える」設計と相容れないため採らない。

## 影響

- `UsersController` に `AuthDbContext` を追加注入した(プロバイダ判定のため)。
- `GET /api/admin/users` に `prefixMatch`(既定 `false`)・`caseSensitive`(既定 `false`)のクエリパラメータを
  追加した。既定値は変更前の挙動(部分一致・大文字小文字を区別しない)と同じにし、後方互換を保つ。
- フロントエンドのユーザー一覧検索フォームに「前方一致検索」「大文字小文字を区別」のチェックボックスを追加した。
- 見直す条件: SQLite 以外のテスト用プロバイダを追加する場合、そのプロバイダの LIKE の大文字小文字の仕様を
  確認し、必要なら分岐を追加する。
